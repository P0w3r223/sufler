## Correction of record — PKD vintage (2026-09-07, after acceptance)

**This ADR specifies PKD 2007 throughout; the shipped dictionary is PKD 2025, and 2025 is
correct.** The 2007 choice rested on one hand-written line in `tests/conftest.py` that finding F7
cited as though it measured the API. Every `rokPkd` the register actually returns is `2025`
(11 occurrences, three files — `docs/decisions.md`), and `6201Z`, the classic software code, does
not exist in the 2025 classification at all. Read every "PKD 2007" below as "PKD 2025", and
`ceidg_tool/data/pkd2007.yaml` as `pkd2025.yaml`; the "Revisit when" trigger inverts likewise. The
rest of the design is unaffected — the vintage was a fact about the register, not a decision about
the architecture. Left in place rather than rewritten, because an accepted document that quietly
changes its own facts is worse than one carrying a dated correction at the top.

## Context

Phases 0-3 delivered the seam this phase plugs into and nothing else: `Criteria` is the only
contract between any input and any fetch (`criteria.py`), `flow.py` holds one decision sequence,
and `criteria.describe()` already carries the docstring *"generowane przez kod (nie przez model) —
faza 3/4"*. The assistant is therefore not a new pipeline; it is a **fourth producer of `Criteria`**,
standing beside CLI flags, the YAML query file and `wizard.collect_criteria`.

What the requirement asks for is narrow and worth restating before any design: a language model turns
a plain Polish sentence into validated `Criteria`, proposes PKD codes **from a dictionary**, and
explains what the API cannot do. It calls no CEIDG endpoint, writes no file, and **the confirmation
summary is generated by code**. `UZUPELNIENIE_01 §B` adds the data rule: what reaches the model is
the question text and the PKD dictionary — fetched records never.

Four things settled by the owner and treated here as given: a separate HTTP client with its own
allowlist; a second credential (an Anthropic API key); the official PKD 2007 dictionary bundled as a
static resource with codes outside it rejected; and `claude-opus-5` through the official `anthropic`
Python SDK, available by default as one of the wizard's paths.

Six facts from the tree shape every decision below. Each was checked, not assumed:

1. **Boundary rule 11 does not see the second HTTP stack.** `tests/test_boundaries.py:608-644`
   matches `httpx.Client` and `Client` imported from `httpx`, **by literal module name**. `anthropic`
   1.x is built on `httpx2`, a different distribution from the pinned `httpx==0.28.1`. So
   `httpx2.Client(...)`, `anthropic.DefaultHttpxClient(...)` and a bare `anthropic.Anthropic()` — which
   constructs a client internally with `trust_env` at its default — all pass a rule that reports itself
   closed. This is the same shape as ADR-0009's finding that the `cli.py` scan saw only `rich` while
   `typer.echo` walked straight through.
2. **The egress policy is one week old and accepted in writing** (`docs/status.md`, "Decisions taken
   by the owner (2026-09-07)"). `httpclient.py` closes three distinct holes with three distinct
   mechanisms, and the review of that work found the first draft had conflated them, with the only
   load-bearing one untested. Nothing here may weaken it for CEIDG traffic, and
   `tests/resilience/test_egress_allowlist.py` plus the suite-wide `no_name_resolution` fixture must
   keep passing unchanged.
3. **`config.mask_tokens` is JWT-shaped, not secret-shaped** (`config.py:62-70`). `richtext.safe`
   calls it, `logsetup.MaskingFormatter` calls it, and `tests/resilience/test_s7_token_leak.py` greps
   a whole session for the CEIDG token. An `sk-ant-…` key matches none of that.
4. **No PKD dictionary exists.** `criteria.normalize_pkd` validates `^\d{4}[A-Z]$`. And
   `docs/decisions.md:31` records that a `pkd` value the API does not recognise returns **204, not
   400** — so a hallucinated but well-shaped code returns "Brak firm spełniających kryteria" and the
   operator cannot tell a hallucination from an empty register.
5. **`flow.prepare_fetch:130` skips the split proposal when `criteria.max_rekordow is not None`.** A
   model that sets a record cap because the sentence said "kilka firm" would disable resilience
   scenario 9's guard without anyone noticing.
6. **`Events` has five progress channels** and ADR-0010 named exactly five as the trigger for
   generalising the protocol. A model call is one request that takes tens of seconds, and CLAUDE.md
   counts silence in requests.

## The shape that follows from the requirement

The assistant produces a `Criteria` and stops. Everything downstream is untouched:

```
opis (one Polish sentence)
   |  assistant.interpret()   <- 1 model request, 0 CEIDG requests, 0 files
   v
AssistantResult(kryteria: Criteria, kody_pkd: [...], ograniczenia: [enum...])
   |  ui/texts.interpretation()  <- code-authored block: criteria.describe(),
   |                                PKD names from the LOCAL dictionary,
   v                                limitation sentences from a code catalogue
operator confirms  (zatwierdz_interpretacje: tak / popraw opis / pytania / wyjdz)
   |
   v
flow.prepare_fetch(...)   <- UNCHANGED: resume -> report -> exactly one count -> cost table -> ...
```

The step is strictly **upstream** of the one decision sequence. That is what keeps
`tests/test_ui_flow.py`'s "exactly one count request per criteria version" green by construction
rather than by care, and it is the answer to *what the operator confirms before a single CEIDG
request is spent*: the interpretation, priced at zero CEIDG requests, before `count` is ever sent.

## Decision 1 — where the model's socket is governed

`client._checked_host` checks a string; `AllowedHostsTransport` checks the socket. The second HTTP
stack needs the same treatment, and the question is who builds it.

### Option A (chosen): `httpclient.py` builds the model client too, over one shared host check

`httpclient.py` gains `build_model_http_client(*, allowed=MODEL_ALLOWED_HOSTS)`. The host rule
itself becomes one pure function:

```python
def refuse_foreign_host(scheme: str, host: str | None, allowed: frozenset[str]) -> None: ...
```

used by the existing `AllowedHostsTransport` (httpx) and by an httpx2 twin. `anthropic` and `httpx2`
are imported **inside** the factory, so a machine without the SDK still runs the CLI and the wizard —
the precedent is `config.read_token_from_keyring`, which imports `keyring` inside the function for
the same reason. §B's "no dynamic imports" forbids `importlib.import_module(name_from_data)`; a
function-level import of a literal module name is what this codebase already does.

- **Pros**: one place answers "where can a connection go"; one copy of the *rule* (two thin
  adapters, which is exactly ADR-0009's `safe()` shape); the tool still starts without the SDK
  installed.
- **Cons**: `httpclient.py` grows a second library's vocabulary; the httpx2 kwargs
  (`transport=`, `trust_env=`, `follow_redirects=`) must be verified against the installed version
  rather than assumed from httpx 0.28.
- **Effort**: M · **Risk**: Med — the risk is *believing* the httpx 0.28 mechanism carries over.

### Option B: let the SDK build its own client

- **Cons**: `trust_env` defaults to on, so `HTTPS_PROXY` diverts model traffic — the exact defect
  phase 3f closed for CEIDG — and no allowlist exists at the socket. "No connection leaves for a
  host outside an allowlist" stops being answerable by reading one module. Rejected.

### Option C: skip the SDK, call `/v1/messages` over the existing `httpx` client

One HTTP stack, rule 11 untouched, one new host in an allowlist, no new transitive dependency.
Cost: hand-rolled SSE parsing, error taxonomy, and retry semantics we would then own forever.
**Foreclosed by the owner's decision 4** (official SDK). Recorded because it is the option that
would make this ADR two decisions shorter, so a future reader should know it was weighed and why it
is not on the table.

**Decision: A.** Two HTTP stacks is a cost the SDK imposes; two *policies* is a cost we would be
choosing, and this project has twice refused to keep two copies of a security-critical rule.

**Two allowlists, never unioned.** `config.ALLOWED_HOSTS` stays CEIDG-only; a new
`MODEL_ALLOWED_HOSTS = frozenset({"api.anthropic.com"})` sits beside it with a comment saying why
the union is forbidden: the CEIDG client must be unable to reach the model host and the model client
unable to reach CEIDG. `build_deps` already narrows the CEIDG gate to the *selected environment's*
host, so the union is not even reachable today — the comment and a test exist to keep it that way
after the obvious future edit ("just add it to ALLOWED_HOSTS").

## Decision 2 — what happens to boundary rule 11

| Option | Verdict |
|---|---|
| A. Leave rule 11 as "only `httpclient.py` builds `httpx.Client`" and add an unrelated rule for the SDK | Rejected. Two rules for one property is how a property stops being checked: the next HTTP library joins neither. |
| **B (chosen). Restate rule 11 library-agnostically, and add rule 12 as its precondition** | The scan's factory set becomes `{httpx.Client, httpx.AsyncClient, httpx2.Client, httpx2.AsyncClient, DefaultHttpxClient, DefaultAsyncHttpxClient}`. Rule 12: **only `assistant/caller.py` constructs `anthropic.Anthropic`, and every such call passes `http_client=` and `api_key=`.** |
| C. Declare the rule unenforceable with two stacks and drop it | Rejected outright: it is the thing that made §B answerable. |

Rule 12 stands to the SDK as rule 9 stands to rule 10, and as rule 11 stands to §B: it is what makes
the property *syntactic*. Without it, "the SDK client goes through our gate" needs dataflow analysis;
with it, the scan asserts (i) the set of modules importing `anthropic` is exactly one, (ii) inside
it, every `Anthropic(...)` call carries both keywords. Asserting a keyword is **present** is the same
move the rule-10 scan makes when it asserts an argument **is** a neutraliser call.

Two properties recorded so nobody discovers them by weakening the scan:

- **It is syntactic and will reject `Anthropic(**kwargs)`.** That is not a false positive: a client
  whose credentials and transport are assembled elsewhere is precisely what the rule exists to stop.
- **A scan that always passes is indistinguishable from one that works.** Rule 12 ships with its own
  self-test in the shape the rule-11 scan already uses: `Anthropic()` bare → violation;
  `Anthropic(api_key=k)` without `http_client` → violation; `AsyncAnthropic(api_key=k,
  http_client=c)` in the owner module → clean; a foreign class named `Anthropic` → clean.

**Rule 13** joins at the same time, and it is the structural form of §B's phase-4 sentence:
`assistant/*` imports none of `client`, `store`, `pipeline`. Fetched records cannot reach the model
because there is no import edge along which they could travel. Mirrors rule 8, same scan shape.

## Decision 3 — how a sentence becomes a `Criteria`

### Option A: have the model emit `Criteria` JSON directly

- **Cons**: `Criteria` is frozen with seventeen fields and validators that raise; its generated JSON
  schema would become a public contract we cannot change without changing the prompt; and a
  validation failure would surface as an SDK parse error rather than as our own message. Rejected.

### Option B (chosen): a permissive `AssistantAnswer`, converted by our code

```python
# assistant/schema.py  (PURE — no anthropic, no httpx, no httpx2)
class AssistantAnswer(BaseModel):
    model_config = ConfigDict(extra="forbid")
    wojewodztwo: list[str] = []
    powiat: list[str] = [];  gmina: list[str] = [];  miasto: list[str] = []
    ulica: list[str] = [];   kod: list[str] = []
    nazwa: list[str] = [];   imie: list[str] = [];   nazwisko: list[str] = []
    nip: list[str] = [];     regon: list[str] = []
    pkd: list[str] = [];     status: list[str] = []
    data_od: str | None = None
    data_do: str | None = None
    szczegoly: bool = False
    ograniczenia: list[OgraniczenieKod] = []   # enum, see decision 6
```

Conversion is ours: PKD codes are checked against the dictionary **first** (so the message is "kod
9999Z nie istnieje w PKD 2007", not a shape error), then `Criteria(**kwargs)` runs the real
validator. Every code and every parameter therefore passes `criteria.py`, which is the requirement,
stated as a call graph rather than as a promise.

Two fields are **deliberately absent from the schema**, and this is the sharpest concrete decision in
this ADR:

- **`max_rekordow`.** `flow.prepare_fetch:130` skips the whole over-threshold branch when a cap is
  set, and `tests/resilience/test_s9_large_count.py` is the test that guards it. A model that reads
  "kilka firm" as `max_rekordow=50` would silently switch off resilience scenario 9. The cap is the
  operator's, set by flag or in the confirmation step.
- **anything transport-shaped** — `page`, `limit`, `base_url`, environment, token. These are already
  outside `Criteria` (phase2_core.md, "Deliberately outside `Criteria`"), and the reason recorded
  there in 2026-09-05 was *this phase*: "inside `Criteria` the phase-4 assistant could generate
  them". `extra="forbid"` plus the absence of the field is what makes consent non-widenable — not a
  guard, an absence.

### Option C: strict tool use with a `ustaw_kryteria` tool

Equivalent in outcome, more moving parts (a tool loop, a forced `tool_choice` whose availability
varies by model generation). Structured outputs give the same guarantee with one call shape.
Rejected as unnecessary; the instruction permits either.

**Transport of the answer**: `output_config={"format": {"type": "json_schema", "schema": …}}` over a
streamed request, then `json.loads` and `AssistantAnswer.model_validate`. The schema is derived from
the pydantic model with `additionalProperties: false` and every property in `required` — pinned by a
test, because pydantic does not produce that shape by default. Streaming is Decision 8's business.

**Today's date goes in the user turn, never in the system prompt.** "w zeszłym roku" needs it, and a
date in the system prompt is the canonical cache invalidator: it would sit in front of the entire
dictionary and make every request a cache miss. The model emits absolute ISO dates, `Criteria`
validates them, and `describe()` shows `2025-01-01 – 2025-12-31` so an off-by-one-year is visible on
the confirmation screen.

## Decision 4 — the PKD dictionary: sourcing, format, and what it does to the prompt

**Why it is load-bearing and not a nicety.** `docs/decisions.md:31` measured that the API answers an
unrecognised `pkd` with **204, not 400**. So a hallucinated-but-well-shaped code produces
`count = 0`, the flow prints "Brak firm spełniających kryteria", and the operator — the person the
whole tool exists for, who has no API knowledge — has no way to distinguish a model error from an
empty register. The dictionary is the only thing standing between that sentence and the truth.

**Where it lives**: `ceidg_tool/data/pkd2007.yaml`, a mapping `kod -> nazwa` in the canonical compact
form the validator produces (`6201Z`), **sorted by code**, one entry per line, with a header comment
naming the legal source (rozporządzenie RM z 24.12.2007 w sprawie PKD, Dz.U. 2007 nr 251 poz. 1885),
the retrieval date and the retrieval URL.

> **Corrected 2026-09-09.** The file that shipped is **`ceidg_tool/data/pkd2025.yaml`** (728
> subclasses), and its legal basis is therefore **rozporządzenie RM z 18.12.2024, Dz.U. 2024 poz.
> 1936**, in force from 1.01.2025 with the transition from PKD 2007 running to 31.12.2026 — the
> header of the generated file is the authority, not this paragraph. The vintage correction is
> recorded further down; the Dz.U. reference above was left pointing at the 2007 regulation, which
> is exactly the reference-data-from-memory trap this project names as its worst.

`pyproject.toml`'s `[tool.setuptools.package-data]` gains
`data/*.yaml` beside the existing `profiles/*.yaml`. Loading mirrors `apiprofile.load_profile`: a
pure `load_pkd(path=DEFAULT)` so tests can substitute a five-entry dictionary.

Sorting is not cosmetics. The prompt prefix must be byte-identical between requests or prompt caching
never reads; "unsorted serialisation" is the first entry on the silent-invalidator list. A test
asserts the rendered dictionary block is stable across two builds.

**How it is verified** — four checks, because I cannot personally certify a legal classification's
rows by reading them. (The row count itself is unverified: this ADR says 654 in places and the
implementation's constant says 655, because published figures differ on whether the 2017 and 2020
amendments are counted. `scripts/build_pkd.py` prints the count it produced so the number is settled
against the source at build time, and the constant is corrected **with a note saying where the value
came from** — editing it to match whatever the file happened to contain would make the check
self-consistent and worthless.)

| Check | Catches |
|---|---|
| Every key passes `criteria.normalize_pkd` and equals its own normalised form | transcription damage, dotted forms, lowercase |
| Entry count equals a pinned constant | a later edit that silently drops or duplicates rows. The assertion's job is to be **loud**, not to encode a number I remember |
| Every PKD code appearing in `tests/fixtures/` and `tests/conftest.py` (`3030Z`, `6201Z`, `0111Z`, `4711Z`) resolves | drift between the dictionary and what the register actually returns — the same "derive it from real data" move the `UNFILLED_COLUMNS` test made after review |
| Owner spot-checks ~10 codes against the GUS browser, recorded here with a date | wholesale sourcing error, which no self-consistent test can see |

**Prompt shape and caching.**

```
system  = [ static instructions | PKD dictionary ]     <- cache_control: ephemeral, 5 min
messages= [ user: today's date + the operator's sentence ]   <- after the breakpoint
```

Order matters: stable content first, volatile last. Claude Opus 5's minimum cacheable prefix is 512
tokens, so the dictionary caches comfortably.

Estimated cost, ~~to be **replaced by a measurement**~~ — **measured 2026-09-07, run A7: 24 854
tokens read from cache on every call after the first**, so the operator-facing figure is ~25k, not
the 13k that reached `ui/texts.py` from an earlier draft (corrected 2026-09-09). The estimate below
also predates the shipped dictionary, which has **728** subclasses rather than 654, and it assumed
PKD 2007. Estimate as written: 654 entries × ~62 characters
of Polish ≈ 40 kB ≈ **15-20k tokens**, plus ~1.5k of instructions. At $5/MTok input that is roughly
**$0.09 uncached, $0.11 on the first call including the 1.25× write premium, ~$0.01 on a follow-up
within five minutes**. Output at low effort is a small JSON object plus adaptive thinking, another
cent or so. A whole interactive session costs grosze against a fetch that costs hours of wall clock —
which is precisely why the "optimise the dictionary out of the prompt" instinct should be resisted.

### Alternatives weighed

| Option | Verdict |
|---|---|
| **A (chosen). Full dictionary in the cached system prefix** | One round trip (which matters under the silence rule), the model sees all 654 names, no Polish-language search to tune. |
| B. Section headings in the prompt + a local `szukaj_pkd(fraza)` tool | Saves ~18k input tokens per turn and cannot propose an invented code — but the validator already cannot accept one, so the only real gain is cost, and it buys a tool loop, extra round trips and a Polish stemming problem ("budowlane" vs "budownictwo"). Keep as the fallback if volume ever changes. |
| C. Two-stage: 88 divisions, then subclasses within the chosen ones | Two round trips and a second prompt shape for a marginal token saving. Rejected. |

**Vintage — corrected 2026-09-07.** This ADR specified PKD 2007 on the strength of a synthetic
fixture. Measurement says **2025**: every `rokPkd` the register returned carries that value, and
`4933Z` from the production sample exists only in the newer classification. The dictionary is PKD
2025; the rejection message names the vintage explicitly, because rejecting a code from another
vintage looks to the operator exactly like a model error. What the `pkd` query parameter indexes was
measured on 2026-09-07: it matches the code **as stored**, and each record carries one vintage while
the transition runs, so a 2025-only dictionary cannot reach 8.6 % of the sampled records at all
(corrected 2026-09-09 from 25.2 %, which counts records whose *main* code is absent). See
`docs/decisions.md`.

## Decision 5 — where the assistant appears

| Option | Verdict |
|---|---|
| A. A sixth menu item, "Opisz zapytanie zdaniem" | Menu reaches seven entries with resume shown, which is exactly ADR-0008's revisit trigger. Worse: the assistant would be a *different* action from "Pobrać firmy", so it would need its own copy of the post-criteria path. |
| **B (chosen). The first question of `collect_criteria`, with `--opis` as its flag twin** | `collect_criteria` asks one free-text question — *"Opisz, czego szukasz, jednym zdaniem (Enter = pytania po kolei)"* — and an empty answer falls through to today's eight questions unchanged. Menu untouched. Both "Pobrać firmy" and "Pobrać gotowy raport" get it, and so does the **"popraw kryteria"** loop, where a language layer is at its most useful ("tylko aktywne, i od 2020"). |
| C. A separate `ceidg-tool zapytaj` command as the only route | Rejected for the reason ADR-0010 rejected its own option D: it makes the operator run two commands to reach one file. |

the wizard's existing `offer_yaml` will now happily write **from the assistant's output** — the
assistant becomes the fastest way to author a query file.

## Decision 6 — the confirmation, which the model does not write

The instruction is explicit and this is how it is met structurally rather than by discipline.

`AssistantAnswer.ograniczenia` is a **closed enum**, not prose:

```
SPOLKI_W_KRS · BRAK_DANYCH_FINANSOWYCH · DATA_TYLKO_ROZPOCZECIE · KONTAKTY_OPCJONALNE
BRAK_FILTRA_WIELKOSCI · BRAK_FILTRA_BRANZY_POZA_PKD · TYLKO_JDG · RAPORT_BEZ_WYKRESLONYCH
KOD_PKD_Z_INNEGO_ROCZNIKA
```

The ninth member was added after test run A5 (2026-09-07), which found the model translating a PKD
2007 code the operator typed into its 2025 successor **silently**; this ADR listed eight until
2026-09-09.

The model chooses **which** limitations apply. The Polish sentence for each lives in `ui/texts.py`,
authored by us, in the message-catalogue style ADR-0009 established for `cli.py`. The confirmation
block is therefore assertable in tests with no model in sight:

```
Interpretacja
  kryteria         <- criteria.describe(), verbatim
  PKD              <- 4120Z — Roboty budowlane związane ze wznoszeniem budynków…
                      (name from the LOCAL dictionary, never from the model)
  czego nie umiem  <- one code-authored sentence per limitation code
  koszt asystenta  <- rate line, see below
```

Rendering PKD **names from the dictionary** is what turns "the model returned 4120Z" into something
an operator can check. A wrong code is invisible; a wrong *name* is obvious.

| Option | Verdict |
|---|---|
| A. The model writes the summary | Forbidden by the instruction, and rightly: it is the one text the operator acts on. |
| **B (chosen). Structured fields → code-authored block** | Assertable offline, single-sourced with the wizard, and it cannot drift from what `Criteria` actually holds because it *is* `criteria.describe()`. |
| C. Code block plus model prose alongside | Rejected. Two summaries on one screen and the operator cannot tell which one binds. |

**No clarification round trip in v1 — reversed 2026-09-09 by ADR-0017, for the empty case only.**
The rule was: ambiguity ("duże firmy") comes back as a limitation code and a partially-filled
`Criteria`, not as a question; the remedies are "popraw opis" and "pytania po kolei". That holds
wherever the criteria are *partially* filled, and it still does. It never covered the case where
**nothing** is filled — there is no partial result to show and the limitation codes have nothing
to attach to — and there the wizard put an empty interpretation on screen, defaulted the
confirmation to "tak, szukaj", and answered the Enter with `Podaj przynajmniej jedno kryterium`.
ADR-0017 adds one round in exactly that case. ADR-0008 Decision 2's rejection of a session state
machine stays intact: one round, then the ordinary sequence, and the assistant still plugs into
`Criteria` rather than into a session.

**Cost disclosure — withdrawn 2026-09-09.** The interpretation screen carried one rate line
(*"asystent: jedno pytanie to ok. 25 tys. tokenów, ułamek grosza; nie wysyła pobranych rekordów"*,
18 k as first written, corrected to 25 k after run A7 measured it). The owner removed it: unlike the
request cost table, which precedes a fetch and gates a spend the operator can still refuse, this
rate gates nothing — the question has already been asked and paid for by the time the screen
appears, and a fraction of a grosz changes no decision. The egress half of the sentence does not go
with it; the first screen's *"dokąd wysyła asystent"* row states what reaches `api.anthropic.com`
before any key is used. ADR-0010 Decision 4 (rate over total when the multiplicand is unknown)
stands where it applies — the cost table.

## Decision 7 — the second credential

**What the guarantee costs.** `config.mask_tokens` matches `JWT_RE` and nothing else, so an
`sk-ant-…` key is invisible to it — and therefore invisible to `richtext.safe` (which calls it) and
to `logsetup.MaskingFormatter` (which calls it). The existing mechanisms **do not** cover the second
credential; they need widening, not reuse. Concretely:

| Change | Why |
|---|---|
| `config.SECRET_PATTERNS = (JWT_RE, ANTHROPIC_KEY_RE)`; `mask_tokens` masks every pattern | One function keeps its name (CLAUDE.md and phase2_core name it) and gains a second shape. `richtext.safe` and the log formatter inherit it for free. |
| `Settings.anthropic_key: str \| None = field(default=None, repr=False)` | Same treatment as `token`. |
| Resolution order: keyring (`ceidg-tool` / `ANTHROPIC_API_KEY`) → `ANTHROPIC_API_KEY` env → `.env`; **never the SDK's own chain** | The SDK resolves `ANTHROPIC_API_KEY` → `ANTHROPIC_AUTH_TOKEN` → an `ant auth login` profile on disk → federation env vars. A bare `Anthropic()` would spend a credential the operator never gave this tool, `sprawdz-token` could not describe it, and the offline suite's behaviour would depend on the developer's `~/.config/anthropic/`. Rule 12 forces `api_key=` explicitly; a test asserts it. |
| `sprawdz-token` gains one line: assistant key present / absent and its fingerprint | Never the value. Mirrors `token_fp`. |
| `tests/resilience/test_s7_token_leak.py` grows a second secret | The session already greps a full run for the CEIDG token; it now plants both and asserts zero hits for both. This is the only thing that will notice the day someone logs the SDK client's repr. |
| The `anthropic` logger is silenced, and `ANTHROPIC_LOG` is never set by the tool | `MaskingFormatter` is attached to the `ceidg_tool` logger with `propagate = False`. SDK debug logging writes to the `anthropic` logger and would carry request headers past our mask entirely. |

**The stakes differ and the ADR says so**: the CEIDG token's payload carries a PESEL, so its leak is
a personal-data incident; the Anthropic key is a spendable credential, so its leak is a bill and an
impersonation. Same handling, different reason — worth writing down so nobody "simplifies" one of
them away on the grounds that it is not a PESEL.

**The first screen changes, and this is not optional.** `texts.first_screen` currently states
*"dokąd wysyła dane: wyłącznie do API CEIDG (host); brak telemetrii"*. That row is an §A acceptance
criterion, and it becomes false the moment the assistant is used. It splits in two:

```
dokąd wysyłam rekordy   wyłącznie do API CEIDG (dane.biznes.gov.pl); brak telemetrii
dokąd wysyła asystent   treść Twojego pytania i słownik PKD do api.anthropic.com;
                        pobrane rekordy — nigdy
asystent                dostępny  |  niedostępny (brak klucza — jak go dodać: …)
```

## Decision 8 — silence, measured in one long request

A model call is a single request that takes seconds to tens of seconds, over a 15-20k-token prompt.
Under CLAUDE.md's rule that is a stretch of silence in a program the operator is watching, and the
existing progress machinery has no channel for it.

| Option | Verdict |
|---|---|
| A. Non-streaming call plus a static "Pytam asystenta…" line | Cheapest, but it cannot distinguish "the model is thinking" from "the connection hung" — which is the exact distinction the rule exists to preserve. |
| **B (chosen). Stream the response; `Events` gains `on_model(elapsed_s, tokens)`** | Tokens arriving *are* the liveness signal. `ConsoleEvents` renders it as a fifth task with `total=None`, which `_CountColumn` already handles from the report-download work, with the first event fired at `(0.0, 0)` right after the headers — the cadence phase 3g settled. `close()` must clear the fifth task id, and the `close` test that already covers four ids covers five. |
| C. Take ADR-0010's generalisation now (one stage-keyed event) | Deferred, explicitly. It touches every call site of five existing channels in the same change that introduces an LLM and a second HTTP stack — the shape that produced phase 3b's blocked first review. The trigger has fired and this ADR records that it fired; the refactor is its own piece of work. |

Retries are announced through the channel that already exists. `max_retries=0` on the SDK client and
**our own single retry**, so a 429 or a 5xx produces `events.on_wait(seconds, REASON_MODEL_RETRY,
resume_at)` before the pause rather than a silent stall inside the SDK's backoff. That is the same
philosophy as `client.py`'s ladder, and it reuses `ratelimit.py`'s wait-reason constants so
`console.py` keeps one import site (ADR-0009's fix for the hard-coded copy of
`REASON_NO_CONNECTION`). Timeout is set explicitly — the SDK default is ten minutes, which is not an
interactive number.

## Decision 9 — failure modes, each with a named outcome

| Situation | Behaviour |
|---|---|
| **No key** | The description question is not asked; the first screen says the assistant is unavailable and how to add a key. `--opis` without a key → `ConfigError`, exit 3, with the same sentence. Never a crash, never a silent fall-through to the eight questions with no explanation. |
| **`anthropic` not installed** | Identical to "no key". This is why the SDK is an optional extra and the imports are lazy. |
| **Auth refused** (`AuthenticationError`, `PermissionDeniedError`) | `AssistantConfigError(ConfigError)`, exit 3, message masked by the widened `mask_tokens`. In the wizard, control returns to the menu — the existing `CeidgError` handler in `run_wizard` already does this. |
| **Rate limit** (`RateLimitError`) | Read `retry-after`, announce through `on_wait`, one retry, then degrade to "pytania po kolei" with a sentence saying why. An interactive operator must not wait 60 s in silence. |
| **Transport / connection** (`APIConnectionError`, `APITimeoutError`) | Same degradation. The assistant is never load-bearing: the wizard and the CLI stay fully usable without it, which is the requirement. |
| **Malformed answer** — unparseable JSON, schema violation, code outside the dictionary, `Criteria` validation failure | **One** repair round trip: the validator's own message goes back as a second user turn over the identical cached prefix, so the retry is cheap. Then stop. Bounded at two model calls per attempt, so the rate line stays honest. |
| **Empty result** — the model returns nothing usable | `criteria.is_empty()` catches it and the existing `texts.EMPTY_CRITERIA` sentence fires before any request. |
| **Answer validates but is wrong** | The one failure no mechanism can eliminate. Five things reduce it, and the ADR states plainly that they reduce rather than remove it: (i) PKD **names** from the local dictionary, so a wrong code reads as a wrong industry; (ii) `criteria.describe()` verbatim, so a wrong voivodeship or year is on screen; (iii) the enumerated limitation sentences, so "no size filter" is said out loud rather than silently ignored; (iv) `flow.prepare_fetch`'s existing `count` request, which prices the query before fetching — a misread query usually shows up as an absurd count or as zero; (v) "popraw opis" and "pytania po kolei" as first-class answers to the confirmation. The operator confirming a code-generated summary **is** the control, and that is why the summary is code-generated. |
| **Prompt injection through the operator's own sentence** | The blast radius is a wrong query, not an action: the assistant has no tools, no files, no CEIDG client, and its only output is data that must pass `criteria.py`. Model text that reaches the screen passes `richtext.safe` under rule 10, exactly like registry text — the model can emit `[link=…]` just as a company name can. |

## Decision 10 — packaging

`anthropic` is an **optional extra**, not a dependency:

```toml
[project.optional-dependencies]
asystent = ["anthropic>=1,<2"]
```

so "the wizard and the CLI stay fully usable without the assistant" is true at install time and not
only at runtime. §B requires pinned dependencies, so `requirements.lock` is regenerated with the
extra installed and now carries **two** HTTP stacks — `httpx==0.28.1` and `httpx2`. A reviewer should
see that `httpx2` arrives as a transitive dependency nobody chose directly; that is the honest cost of
the SDK and it belongs in the release note. CI installs the extra so `mypy ceidg_tool tests` and the
boundary scans see the real import graph.

### Test strategy

All offline, no TTY, no network, on a `ScriptedAssistant` / `ScriptedCaller` and the existing
`FakeApi` / `FakeClock`.

| What | Pinned |
|---|---|
| `assistant/pkd.py` | Every code normalises to itself; entry count equals the pinned constant; every PKD code in `tests/fixtures/` and `conftest.py` resolves; an unknown code is rejected with a message naming the vintage. |
| `assistant/prompt.py` | The rendered system block is byte-identical across two builds (the caching invariant), and is sorted. |
| `assistant/translate.py` | A well-formed answer becomes exactly the expected `Criteria`; a bad PKD code is rejected **before** `Criteria`; a bad NIP checksum is rejected by `Criteria`; `max_rekordow` cannot be set because the schema has no such field (`extra="forbid"` raises). |
| **§B, behaviourally** | The recorded request contains exactly `prompt.build_system(dictionary)` and a user turn matching the two-substitution template — no record, no token, no path, no data-dir. This is the enforcement of "pobrane rekordy nigdy" at the level of bytes, complementing rule 13's import scan. |
| Egress (model client) | Its **own** three tests, not confidence inherited from the CEIDG ones: a proxy in the environment cannot divert it; `SSL_CERT_FILE` cannot replace the CA bundle (the discriminating test, since deleting that one value left all 654 tests green in phase 3f); a foreign host is refused before any name is resolved. Plus a positive control proving the DNS stub sees httpx2 at all — see finding F3. |
| Cross-gate | The CEIDG client refuses `api.anthropic.com` and the model client refuses `dane.biznes.gov.pl`. The test that stops a future edit from unioning the two allowlists. |
| Boundary rules | Rule 11 restated (six factories, self-test extended); rule 12 (one `anthropic` importer; `Anthropic(...)` always carries `api_key=` and `http_client=`; self-test with four shapes); rule 13 (`assistant/*` imports no `client`/`store`/`pipeline`); rule 6 gains the three pure assistant modules with `anthropic` and `httpx2` in `FORBIDDEN_IN_PURE`. |
| Flow | The description question with an empty answer produces today's exact question sequence; a confirmed interpretation reaches `prepare_fetch` with **zero** CEIDG requests spent; "popraw opis" re-asks and re-interprets without a `count`; `--tak` with `--opis` exits 3; declining spends nothing. |
| Failure modes | No key → question absent and the reason stated; auth error → exit 3 masked; malformed answer → exactly one repair call, then degradation; rate limit → one announced wait, then degradation. |
| Progress | One `on_model` before the first token and at least one per second thereafter; `close()` clears all five task ids. |
| Scenario 7 | The Anthropic key joins the CEIDG token in the full-session grep; zero hits for both. |

### What we explicitly give up

- **No multi-turn conversation.** One sentence in, one interpretation out, plus at most one repair
  call. A dialogue would need the session state ADR-0008 Decision 2 rejected.
- **No clarifying questions from the model.** Ambiguity is a limitation code.
- **The assistant cannot set a record cap**, so "znajdź mi kilka firm budowlanych" still meets the
  over-threshold proposal rather than a silent cap.
- **The tool will not work behind a proxy for model traffic either.** The owner accepted that
  consequence for CEIDG on 2026-09-07; it now extends to `api.anthropic.com`, and on a corporate
  network the assistant fails to connect rather than routing the question through a middleman.
- **PKD 2007 only.** A later vintage in the register is a rejection, not a guess.

## Risks

| Risk | Response |
|---|---|
| httpx2's transport semantics differ from httpx 0.28, so the mechanism believed to kill environment proxies is not the one that does | The model client's three egress tests assert **behaviour** (which names get resolved), not mechanism. This is the exact lesson of the 2026-09-07 review, applied before rather than after. |
| The `no_name_resolution` net does not cover httpx2, so a test could make a real request | Finding F3. A positive control for the model client is a precondition of merging, not a nicety. |
| Prompt caching silently stops working and every question pays full price | Assert `usage.cache_read_input_tokens > 0` on a second identical request in an integration test with a recorded response; the failure mode is silent by construction, so it needs a standing check rather than one look. |
| A convincing but wrong interpretation is confirmed by an operator who trusts the machine | Decision 9's five mitigations, plus the `count` step. Stated as reduction, not elimination. |
| Two secrets, one masking function, and a future third shape | `SECRET_PATTERNS` is a tuple and scenario 7 iterates it. Adding a pattern without adding it to the test is the failure to prevent; the test derives its plants from the tuple. |
| The dictionary is transcribed wrongly at source and every check is self-consistent | Only the owner's spot-check catches this. It is listed as a gate item, not a test. |

## Appendix — findings from reading the documents against the code

| # | Severity | Finding |
|---|---|---|
| **F1** | **High** | `config.mask_tokens` masks JWTs only (`config.py:62-70`). CLAUDE.md and `docs/design/phase2_core.md` state that the token is kept out of logs, messages, the database and output files by `mask_tokens` and `richtext.safe` — but that guarantee is **shape-specific**, not secret-generic. An `sk-ant-…` key passes both verbatim: into `ui/render.ConsoleView.error`, into the rotating log through `MaskingFormatter`, and into any `CeidgError` message. Nothing in the tree would notice, because `tests/resilience/test_s7_token_leak.py:81` greps for the CEIDG token alone. Live the day a key is added, not the day the assistant ships. |
| **F2** | **Medium-High** | The rule-11 scan (`tests/test_boundaries.py:608-644`) is keyed to the literal module name `httpx`: it collects `Client`/`AsyncClient` imported from `httpx` and attribute calls on names bound to `import httpx`. `httpx2.Client(...)`, `anthropic.DefaultHttpxClient(...)` and `anthropic.Anthropic()` (which constructs a client internally, with `trust_env` at its default) all pass. The rule reports itself closed while a second HTTP stack walks through — the same shape as ADR-0009's finding that the `cli.py` scan saw only `rich` while `typer.echo` was open. Fix before the SDK lands. |
| **F3** | **Medium** | The suite-wide `no_name_resolution` fixture (`tests/conftest.py:13-27`) and the §E DNS stub (`tests/resilience/test_egress_allowlist.py:36-50`) both patch `socket.getaddrinfo`. That covers httpx 0.28's sync transport. Whether httpx2 resolves through the same call is **unverified**; if it does not, the safety net silently stops applying to model traffic and a test could make a real request to `api.anthropic.com`. Must be established by a positive control for the model client — the trick `test_an_allowed_host_is_the_only_name_resolved` already uses — not assumed. |
| **F4** | **Medium** | `ui/texts.py:84` hard-codes *"dokąd wysyła dane: wyłącznie do API CEIDG (…); brak telemetrii"*. §A makes the first screen an acceptance criterion, and `tests/test_ui_texts.py` pins its content. Shipping the assistant without changing that row makes an acceptance-criterion screen state a falsehood about where personal-adjacent text goes. |
| **F5** | **Medium** | The `anthropic` SDK resolves credentials from an ambient chain (`ANTHROPIC_API_KEY` → `ANTHROPIC_AUTH_TOKEN` → an `ant auth login` profile on disk → workload-identity env vars). A bare `Anthropic()` would therefore spend a credential the tool never asked for, which `sprawdz-token` could not describe, and would make the offline suite's behaviour depend on the developer's `~/.config/anthropic/`. `api_key=` must always be explicit; rule 12 is what makes that checkable. |
| **F6** | **Medium** | `progress.Events` carries five channels (`on_request`/`on_wait` aside: `on_page`, `on_details`, `on_export`, `on_download`, plus `on_message`). ADR-0010's closing paragraph named **five** as the trigger to generalise the protocol into one stage-keyed event. Phase 4 needs a sixth, so the trigger has fired. This ADR takes the sixth channel and defers the refactor deliberately (Decision 8, option C) rather than letting the trigger pass unremarked. |
| **F7** | **Medium — confirmed 2026-09-07, and the conclusion inverted** | The finding was right that nothing in the tree distinguishes PKD vintages, and wrong about which vintage applies. It cited `tests/conftest.py` as evidence that "the API returns `rokPkd: 2007`" — but that line is a **hand-written test double**, not a measurement. Every `rokPkd` in real API data says **2025** (11 occurrences, three files; see `docs/decisions.md`). The dictionary is therefore PKD **2025**, and the risk the finding described was real but pointing the other way: a 2007 dictionary would have rejected codes the register actually uses, such as `4933Z`, which exists only in the newer classification. The fixture has been corrected so the double no longer contradicts the API. **Measured 2026-09-07**: the `pkd` **query parameter** matches the code as stored on the record, and the register is mid-transition — 58.6 % of 285 026 real records still carry PKD 2007 codes, and **8.6 %** of them carry no code the 2025 dictionary knows (corrected 2026-09-09; the 25.2 % this row carried counts records whose *main* code is absent, which is a different question). The dictionary stays 2025 (that is what the register returns in `rokPkd` and where the confirmation screen's names come from), but it is **not sufficient on its own** until the transition ends on 31.12.2026. See `docs/decisions.md`. |
| **F8** | **Low-Medium** | `docs/decisions.md:31` records that an unrecognised `pkd` value returns **204 (no match), not 400**. Nothing guards the consequence: a well-shaped but nonexistent code produces `count = 0` and the flow's "Brak firm spełniających kryteria", which is indistinguishable from an empty register. That measured behaviour is the whole argument for the dictionary, and it is currently recorded in `decisions.md` without any code reflecting it. |
| **F9** | **Low** | `pyproject.toml` declares `httpx>=0.27` with no upper bound and no notion of a second HTTP stack; §B requires pinned dependencies in a lock file. Adding `anthropic` introduces `httpx2` as a transitive dependency nobody chose directly. Making `anthropic` an optional extra is what keeps "usable without the assistant" true at install time as well as at runtime. |

## Revisit when

The register returns a `rokPkd` other than `2007` (the dictionary's vintage becomes a dialect fact
and probably belongs beside `ApiProfile`); the assistant needs to drive a whole session rather than
produce one `Criteria` (ADR-0008 Decision 2's session state machine becomes worth its cost); the
progress protocol is generalised (Decision 8 option C, whose trigger has already fired); a third
outbound destination appears (at which point `httpclient.py` wants a registry of
`(purpose, allowlist)` rather than two named factories); or measured cost makes Decision 4 option B
(a local PKD search tool) worth its extra round trip.

## Gate

Before implementation: owner approval of this ADR, and the PKD spot-check (Decision 4, verification
row four). Before merge: the model client's own three egress tests green, the F3 positive control
established, rules 11-13 enforced with self-tests, and the token measurement replacing the estimate
in Decision 4.

**Precursor shipped 2026-09-07**, ahead of and independent of this design: F1 (masking was
JWT-shaped) and F2 (rule 11's scan was `httpx`-shaped) were both live in the tree and are closed —
`mask_tokens` now masks registered secret *values* as well as known shapes, which also covers the
opaque non-JWT token `inspect_token` supports, and rule 11's scan is data-driven across `httpx`,
`httpx2` and the SDK's re-exported factories, over `ceidg_tool/`, `tests/` and `scripts/`. Two
things this ADR still owes: **rule 12 is the only thing that will catch `Anthropic(...)`**, which
rule 11 deliberately does not cover, and `HTTP_CLIENT_MODULES` names `httpx2` on the strength of the
SDK's documentation rather than an installed package — so **CI installing the `asystent` extra
(Decision 10) is a gate item, not prose**: until the scans see the real import graph, the second
stack's module name is an assumption.
